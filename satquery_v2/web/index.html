Ask a satellite image what it is looking at.

SatQuery routes your question to the right workflow, runs a fine-tuned vision-language model over the imagery, measures the pixels itself, and hands back an answer you can check line by line.

Open the console How it works

Single image

Ask what a scene contains. You get the model's reading plus a measured land-cover breakdown in pixels and percent.

Change detection

Two dates, one area. Changed pixels, changed area, and distinct regions are counted from the imagery, not narrated.

Optical + SAR

Radar sees through what optical cannot. Where the two sensors agree is where a detection is worth trusting.

Visible working

Every run shows its execution trace: which workflow ran, what was measured, and which half of the answer came from the model.

A model may describe a change. It may not measure one.

Semantic content — what the scene is, which classes are present — comes from the fine-tuned model. Every number comes from NumPy, computed on your actual pixels. The two are never blended, and each answer says which part came from where. If the model fails to load, the measurements survive intact and the answer tells you so.

    What happens when you press Analyze
    
        
      
          
    1. Input validation checks format, band count, and whether
              a pair covers the same footprint. Mismatched sizes are resampled;
              mismatched projections are refused, because resampling across them
              would misregister every pixel.
      2. 
          
    2. The router classifies your question into one of six
              tasks and picks the workflow that fits the images you supplied.
      3. 
          
    3. The vision-language model is asked for semantics —
              what the scene is.
      4. 
          
    4. NumPy computes every number: pixel counts, changed
              area, region counts, class breakdowns.
      5. 
          
    5. The synthesizer assembles the answer and labels which
              part came from where.
      6. 
        
    

        
    Two kinds of confidence
    
        
    When the model answers, SatQuery reports generation
           confidence: the mean probability the decoder assigned to the
           tokens it actually produced. That is a real measurement of how sure the
           model was of its own wording. It is not a class probability, and
           the interface never relabels it as one.
    
        
    When the local specialists answer instead, the confidence shown is a
           heuristic derived from how dominant the leading land-cover class is.
           The results panel says which kind you are looking at.
    

        
    Band layout changes the answer
    
        
    Land-cover classes are defined by spectral indices, not by colour.
           Without a NIR or SWIR band, shadow reads as water and bright soil reads
           as buildings. On the built-in benchmark, supplying the correct band
           roles moves overall accuracy from 64.8% to 93.8%.
    
        
    If you leave the preset unset, SatQuery falls back to RGB colour proxies
           and says so in the trace rather than guessing silently.

    When the model is unavailable
    
        
    Loading a multi-billion-parameter model needs disk, memory, and usually
           a GPU. If it cannot load — no token, gated repo, out of memory, no
           PyTorch — the console keeps working on local specialists and marks the
           answer Source: local specialist. Nothing is fabricated to
           fill the gap, and every measured number is unaffected.
    

        
    API
    
        
    The same functionality is available as JSON. Interactive docs are at
           /api/docs.
    

    curl -X POST http://127.0.0.1:8000/api/analyze \
  -F mode=single \
  -F "query=What is present in this image?" \
  -F image_a=@scene.tif
